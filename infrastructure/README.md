# infrastructure

Everything here targets **IBM Code Engine** and **OAuth2 (Keycloak, `client_credentials`)** only.
The runnable stack comes from the separate repository
[galaxium-travels-infrastructure-tsuedbro](https://github.com/thomassuedbroecker/galaxium-travels-infrastructure-tsuedbro),
release `v6.2.4` (see its `deployment/ibm-code-engine/DEPLOY-PATH-B-OAUTH2.md`).

> **Naming:** "Path A" and "Path B" in *this* repository mean **A = deploy** and **B = import an existing deployment**.
> The "Path B" in the upstream file name is the upstream name of its OAuth2 Code Engine variant (the one Path A deploys). They are unrelated.

Both paths end with the same file, `galaxium-endpoints.env`. Everything after it (verification,
`watsonx-orchestrate-adk/` scripts) works the same.

## Which path?

| | Path A — deploy from scratch | Path B — existing deployment (infrastructure repo **not** cloned here) |
|---|---|---|
| Use when | You want to create the stack | The stack was deployed from another repository or by someone else |
| Clones the infrastructure repo into `infrastructure/` | Yes | **No** |
| You provide | `IBM_CLOUD_API_KEY` | `deploy.env.oauth2` + `deployment-links.env` (copied from the deployer, saved in `infrastructure/`) |
| `IBM_CLOUD_API_KEY` needed? | Yes | Only for `import_existing_deployment.sh --code-engine` and `inspect_code_engine.sh` |
| Folder | `path-a-deploy/` | `path-b-existing/` |
| Guide | [1.1 – 1.7](../1-galaxium_setup.md) | [1.8](../1-galaxium_setup.md) |

```sh
# Path A
cp infrastructure/.env_template infrastructure/.env      # set IBM_CLOUD_API_KEY
bash infrastructure/path-a-deploy/deploy_code_engine_oauth2.sh

# Path B
bash infrastructure/path-b-existing/import_existing_deployment.sh \
  --links infrastructure/deployment-links.env \
  --deploy-env infrastructure/deploy.env.oauth2

# Both paths
bash infrastructure/verify_code_engine_oauth2.sh
```

## Inspect Code Engine

Shows pods, deployments, configmaps and logs of the Code Engine project with `kubectl` (both paths):

```sh
bash infrastructure/inspect_code_engine.sh                                  # pods, deployments, configmaps
bash infrastructure/inspect_code_engine.sh log-follow galaxium-booking-mcp  # live log (Ctrl+C to stop)
bash infrastructure/inspect_code_engine.sh log        galaxium-booking-mcp  # saved to infrastructure/logs/
```

- Omit the app name for `log` / `log-follow` to pick a running pod from a menu.
- Needs `infrastructure/.env` (`IBM_CLOUD_API_KEY`), `ibmcloud` with the `code-engine` plugin, `kubectl` and `jq`.
- `CE_PROJECT_NAME` (default `galaxium-travels-oauth2`) and `IBM_CLOUD_REGION` (default `us-south`) come from `.env` or `deployment-links.env`.

## Layout

```text
infrastructure/
├── .env_template                  shared: copy to .env, set IBM_CLOUD_API_KEY (Path B: only for --code-engine and inspect_code_engine.sh)
├── verify_code_engine_oauth2.sh   shared: 401 without token, no implicit flow, token, initialize, tools/list
├── inspect_code_engine.sh         shared: kubectl view of pods, deployments, configmaps and logs (needs kubectl, jq)
├── galaxium-endpoints.env         generated by A or B, used by verify and the ADK scripts (git-ignored)
├── path-a-deploy/                 Path A: deploy from scratch
│   └── deploy_code_engine_oauth2.sh      actions: deploy (default), prepare, endpoints
├── path-b-existing/               Path B: existing deployment, infrastructure repo NOT cloned
│   ├── import_existing_deployment.sh     --links <file> or --code-engine, optional --deploy-env <file>
│   └── deployment-links.env_template     minimal deployment-links.env (two URLs)
├── deploy.env.oauth2              Path A: generated, Path B: copied from the deployer (contains secrets, git-ignored)
├── deployment-links.env           Path B input, optional location for inspect_code_engine.sh (git-ignored)
├── logs/                          log files saved by inspect_code_engine.sh (git-ignored)
└── galaxium-travels-infrastructure-tsuedbro/   Path A only: clone of the infrastructure repo (git-ignored)
```

Scripts that exist only inside the infrastructure repo itself are in `deployment/ibm-code-engine/`
(on Path A: `infrastructure/galaxium-travels-infrastructure-tsuedbro/deployment/ibm-code-engine/`):

| Script | Purpose |
|---|---|
| `export-deployment.sh --oauth2` | Export live links and configuration (no secrets) to `generated/exports/` |
| `teardown-stack-oauth2.sh` | **Deletes** the applications, configmaps and secrets (keeps the Code Engine project). Run it when you are done to stop Code Engine costs, see [Guide 1.6](../1-galaxium_setup.md) and the [cost estimate](../README.md#cost-estimate). |

On Path B, run these from the repository that did the deployment. Do not tear down a stack that someone else still uses.

Full explanation: [1-galaxium_setup.md](../1-galaxium_setup.md).
